# Firebase trial build — 2026-09-20

## Verified

- TypeScript type checking, Vite build and Capacitor asset synchronization.
- 42 local Firestore emulator assertions: account roles, own-profile access,
  provider moderation, clinic/lab ownership, request privacy/status transitions,
  completed-request ratings, advertisement publication and visibility.
- 17 checks against the live `deroua-service-8c82a` backend: administrator login,
  customer/provider/clinic/lab account creation and re-login, persistence, provider
  approval, facility edits, request lifecycle, ratings, advertisements, and denied
  unauthorized operations. All generated test accounts and records were deleted.
- Email/password and Firestore connectivity checked with a separate disposable
  account, also removed. No existing PocketBase data was removed or migrated.
- Admin login and dashboard rendering through the actual web interface; session
  restored correctly after page reload.
- Firestore rules published through Firebase Console with user approval. Admin
  role provisioned for the approved Ibrahim account; passwords not stored in code.

## Fixes included

- Connected the web/Capacitor SDK to the correct Firebase project and default DB.
- Restore authentication asynchronously and obtain role/phone from server profile.
- Admin status requires a protected role, not an email comparison or local flag.
- Ignore undefined optional Firestore properties (previously broke ad creation).
- Do not claim success or discard form contents when ad/request/rating saving fails.
- Approval, rejection, badge changes and deletions update UI only after persistence.
- Query public providers/ads according to rules; provider can also read own pending profile.
- GPS failure asks for manual address instead of fabricating an address.
- Complaint errors no longer masquerade as successful sending.
- Removed global account-deletion link; deletion request remains in account dashboard.
- Disabled unconfigured Google sign-in UI; email/password is the tested method.
- Corrected mandatory-email wording; replaced placeholder ad-contact telephone with support email.

## Not complete / not approved for store publication

- Images: Firebase Storage is not used and billing remains untouched. The separate
  Oracle image service is prepared but NOT deployed or configured in the app.
  Avatar uploads will report that the service is not connected.
- Account deletion: currently a deletion-request link, not an automatic cascade.
- Existing PocketBase accounts, providers, requests and photos are not migrated.
  Create new trial accounts in Firebase. The approved admin account is configured.
- Google sign-in, push notifications, full offline behavior, Play policies/privacy
  updates, release signing/AAB and store submission were not certified by these tests.
- No Android device is attached to adb: no on-device install, WebView, camera,
  geolocation, notification or device-specific tests were performed.
- Backend checks are not a claim that every UI interaction or edge case was tested.
- Dependency audit still has moderate findings; bundle size warning also remains.

## Suggested trial

Create one account per role using different emails. For the provider, approve its
pending application from the admin dashboard before looking for it as a customer.
Test request acceptance/completion/rating, clinic/lab edits, and ad publication.
Report the account role, action, screenshot and error message for any failure.
